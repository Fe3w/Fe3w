## Featured projects

**Loop Vectorization Analyzer (LLVM compiler plugin)** · Personal Project · Nov 2026 · [Repo](https://github.com/Fe3w/Loop-Vectorization-Analyzer) · [Write-up](https://github.com/Fe3w/Loop-Vectorization-Analyzer/blob/main/docs/writeup.md) · [Bug reproducer](https://github.com/Fe3w/Loop-Vectorization-Analyzer/blob/main/test/interchange/confused-miscompile.test)

LLVM 20 pass plugin in C++ that explains why the loop vectorizer rejects a loop, with 204 lit/FileCheck tests in GitHub Actions.

- **168 of 180** mostly held-out TSVC loops (93.3%, x86-64): the plugin's reason matches LLVM's own.
- **13 of 14** suggested fixes make LLVM vectorize the loop. The repair transform reached up to **5.79x** on cholesky with `-ffast-math -march=native` (1.05x in strict FP), with 60 of 60 strict-FP outputs byte-identical.
- **Wrong-result bug** in LLVM 20.1.2's loop-interchange pass found and reproduced (checksum 1,961,666 to 171,990), fixed in LLVM 21.

**SysArray: 8x8 int8 systolic-array GEMM accelerator** · Personal Project · Nov 2026 · [Repo](https://github.com/Fe3w/systolic-array-gemm-accelerator)

Weight-stationary 8x8 array in SystemVerilog with DMA, buffers, int32 accumulator and command controller, plus a Python tiling compiler and cycle-accurate performance model.

- **1,000 of 1,000** random GEMMs generated by the tiling compiler match NumPy (cocotb + Verilator tests written before each block's RTL).
- **0.44 to 0.78** utilization from double buffering on a 256x256x256 GEMM (**1.77x fewer cycles**). The performance model predicts hardware cycles exactly in 16 of 16 runs.
- **60.55 to 98.93 MHz** core clock in the FPGA flow (Lattice ECP5, Yosys + nextpnr). **1.05 mm² core** in the ASIC flow (SkyWater SKY130, OpenROAD), placed and routed, timing met at 66.7 MHz.

**CPU and GPU kernel optimization and Roofline profiling** · B.Tech Specialization Project and Conference Paper · 2026 · [Project report](https://drive.google.com/file/d/1XhWOYI6mYyLRbKIm25UFTFQibAgZOgr0/view?usp=sharing) · [Paper](https://drive.google.com/file/d/1Iqg1ht8dw_D7Ud5cnDXnYjy3pSv4l__W/view?usp=sharing) · [Code](https://github.com/Fe3w/GPU-CPU-Performance-Profiling_and-Optimization)

C++ and CUDA kernels on an Intel i7-13650HX CPU and RTX 4060 Laptop GPU, all 34 runs verified against a double-precision reference. The paper was presented and defended at a conference before a review panel.

- **50.1x** over an unfused baseline for a FlashAttention-style fused attention kernel at 0.03% error (online softmax, FP16 Tensor Cores).
- **114x** on CPU GEMM (0.73 to 83.4 GFLOP/s) with cache blocking, OpenMP and AVX2.
- **24x** less DRAM traffic from fusion but only 15% less runtime (Nsight Compute), so register tiling and Tensor Cores drove the speed-up.

**Neuro-symbolic VLA for robotic pick-and-place (Dobot Magician)** · B.Tech Project · 2026 · [Repo and demo video](https://github.com/Fe3w/dobot-vlm-vla-pick-place)

A VLM makes symbolic choices (target, reference object, relation) and a kinematics layer turns them into arm motions, validated in NVIDIA Isaac Sim. Python serial driver and ArUco-marker localization.

- **40 s to under 8 s** decision time, with no paid-API dependence, by distilling larger models into local VLMs with LoRA.
